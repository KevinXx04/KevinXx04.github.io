Mobile Test Automation Suite — MiniTaskApp

End-to-end mobile automation with Appium, Python & Flutter

Project Description

Personal project combining a Flutter task management app as the system under test with a full end-to-end mobile automation suite. Built a Flutter (Dart) app featuring login, CRUD task operations, and confirmation dialogs, then designed and implemented an Appium-based test suite using the Page Object Model (POM) pattern in Python to automate 12 test scenarios on a physical Android device.

Project Architecture

Two-layer architecture: the Flutter app as the system under test and the Python/Appium suite as the test layer:

  • Flutter App (SUT): Login screen, task list with CRUD operations, confirmation dialogs — compiled and deployed on a physical Android device via ADB
  • Page Object Model: Dedicated page classes (LoginPage, TaskPage, EditPage) encapsulating element locators and interaction methods
  • Test Suite: 12 pytest test cases covering login validation, task creation, editing, deletion, and full workflow scenarios
  • Appium Driver: Flutter driver integration for precise element locating via semantic labels

Technologies Applied

  • Flutter & Dart — Cross-platform mobile app (system under test)
  • Python — Test automation scripting language
  • Appium — Mobile automation framework with Flutter driver
  • pytest — Test runner and assertion framework
  • Android & ADB — Physical device deployment and debugging
  • Page Object Model — Design pattern for maintainable test structure
  • Git — Version control

Key Features

  • 12 Automated Test Cases: Login validation, task CRUD, editing workflows, and confirmation dialogs
  • Page Object Model: Clean separation of locators and test logic for easy maintenance
  • Physical Device Testing: All tests executed on a real Android device via ADB
  • Flutter + Appium Integration: Uses Appium's Flutter driver for semantic element locating
  • Full SUT Ownership: App designed and built from scratch specifically for this automation exercise

Frontend Management System - FUNCAVIDA

Comprehensive web management system for a Costa Rican foundation

Project Description

Frontend system developed for FUNCAVIDA (Cancer Life Foundation), a Costa Rican organization dedicated to supporting cancer patients. The web application enables comprehensive management of cancer survivors, sponsors, volunteers, venues, assets, categories, and emergency contacts.

The system includes advanced features such as JWT authentication, granular permission system by window, bulk data export to Excel with corporate styles, statistics system with interactive visualizations (Chart.js), secure session management, and reusable modals for success/error messages. It comes with seeders to generate test data and complete technical documentation for all modules.

Project Architecture

MVC Frontend Architecture with ES6 modules: Single Page Application (SPA) that consumes an external REST API. Uses a responsibility separation pattern with an organized folder structure in View, Controller, and Core.

  • View/ - HTML views organized by module (User, Cancer, GodParent, Headquarter, Assets, Category, EmergencyContact, Survivor, Volunteer)
  • Controller/ - Business logic in modular JavaScript:
    • api{Module}.js - HTTP client for communication with REST API using fetch
    • index{Module}.js - Module orchestration and event handling
    • list{Module}.js - List rendering with dynamic filters
    • form{Module}.js - Validation and form submission
    • utils/ - Shared utilities (JWT, permissions, modals, Excel export, API client)
  • Core/ - Authentication middleware and centralized error handling
  • Content/ - Unified CSS styles with CSS variables and responsive design
  • seeders/ - Test data generators for sponsors and venues
  • docs/ - Detailed technical documentation for each module and utility

Technologies Applied

  • JavaScript ES6+ - Native modules, async/await, destructuring
  • HTML5 - Semantic and accessible
  • CSS3 - Custom Properties, Grid, Flexbox
  • jQuery 3.7.1 - DOM manipulation and AJAX
  • Chart.js 4.4.0 - Interactive charts (bar, line, pie)
  • xlsx-js-style 1.2.0 - Excel export with corporate styles
  • Express.js 4.19.2 - Static file server
  • JSON Web Tokens (JWT) - Secure authentication and authorization
  • Fetch API - Communication with REST API
  • Git - Distributed version control

Key Features

  • 🔐 Authentication & Authorization System: Secure login with JWT, password recovery, granular permissions by window, automatic session validation
  • 📊 Reporting & Statistics System: Interactive visualizations with Chart.js, export to Excel with FUNCAVIDA corporate styles
  • 👥 Management of 9 Complete Modules: Survivors, Sponsors, Volunteers, Venues, Assets, Users, Categories, Emergency Contacts, Cancers
  • 🛠️ Reusable Utilities: ApiClient, ExcelExporter, JWT Manager, Modals System, PermissionsManager (~600 lines of duplicated code eliminated)
  • 🌱 Seeders for Testing: Automatic generators of 100 records with realistic Costa Rican data
  • 📚 Technical Documentation: 18 documentation files with usage guides and examples

Frontend Management System - CCSS Consultory

Final assessment project — Onboarding / Induction Program

Project Description

Practice project developed as the final assessment of a frontend development induction program. A comprehensive medical consultation management web application built as a React SPA for the Caja Costarricense de Seguro Social (CCSS). The system provides doctors and administrators with a complete interface to manage patients, diseases, medications, diagnoses, and users. Its defining feature is the "Modo Atención" (Triage UI), an intelligent priority queue that automatically sorts pending patients by the severity of their diagnosed condition, streamlining the doctor's workflow by always surfacing the most critical case first.

Project Architecture

Frontend architecture based on React 18 with a component-driven SPA approach, communicating with a Laravel REST API backend:

  • React Router v6 with lazy-loaded routes and protected route guards for authentication
  • Context API for global state: AuthContext (session management) and ActivityContext (cross-module activity logging persisted in localStorage)
  • Axios-based API layer with centralized service wrappers for all backend resources
  • Generic reusable DataTable component with pagination, search, and injectable custom actions
  • Multi-stage Docker build served via Nginx for production deployment
  • Jenkins CI/CD pipeline for automated build and deployment (QA / main branches)
  • Core modules and features:
    • Modo Atención (Triage UI) — Priority queue that evaluates disease severity (High / Medium / Low) and auto-sorts pending patients
    • Diagnoses — Tab system with Pendientes / Atendidos; auto-routes patient to "attended" upon saving a new diagnosis
    • Patients — Full CRUD for patient registration and management
    • Diseases — Catalog linked to a Priority that feeds the Triage engine
    • Drugs — Medication inventory management
    • Users — Role management for Doctors and Administrators
    • Dashboard — Real-time stats and global activity timeline with quick-action shortcuts

Technologies Applied

  • React 18 — Component-based UI library for building the SPA
  • TypeScript — Statically typed JavaScript for safer, more maintainable code
  • Vite — Fast build tool and development server
  • Tailwind CSS — Utility-first CSS framework for responsive styling
  • Radix UI — Accessible headless component primitives (dialogs, dropdowns, tabs, etc.)
  • React Router v6 — Client-side routing with lazy loading and protected routes
  • Axios — HTTP client for REST API communication with the Laravel backend
  • React Hook Form — Performant form state management and validation
  • Recharts — Composable charting library for dashboard data visualization
  • Sonner — Toast notification system for user feedback
  • Docker + Nginx — Containerized multi-stage production build
  • Jenkins — CI/CD pipeline for automated deployment across QA and production branches
  • Git — Distributed version control for collaborative development

Minesweeper with React

Modern implementation of the classic Minesweeper game

Project Description

Reimplementation of the iconic Minesweeper game using React with modern hooks and Redux Toolkit for state management. Includes multiple difficulty levels, real-time timer, remaining mines counter, flag system, and automatic detection of victory or defeat.

Project Architecture

React application with functional components, hooks, and Redux Toolkit for global state, structured for maintainability and scalability:

  • Minesweeper - Main component that manages the game state and timer
  • Board - Component that renders the game board cells
  • Cell - Individual component for each board cell with reveal and flag logic
  • GameControls - Controls to change difficulty, restart game, and show statistics
  • WinModal - Modal that appears upon winning, showing time and difficulty
  • minesweeperSlice - Redux slice with game logic, board generation, mine placement, and recursive reveal algorithms
  • Game states: idle, playing, won, lost
  • Recursive reveal algorithm for adjacent empty areas

Technologies Applied

  • React 19 - Library for user interfaces with functional components
  • JavaScript ES6+ - Arrow functions, destructuring, modules, and async/await
  • CSS3 - Styles with CSS variables, flexbox, and animations
  • React Hooks - useState, useEffect, useSelector, useDispatch
  • Redux Toolkit - Global state management with slices and reducers
  • Vite - Fast build tool and development server
  • Git - Version control

Key Features

  • Multiple Difficulties: Easy (5x5, 5 mines), Medium (10x10, 15 mines), Hard (20x20, 60 mines)
  • Timer: Real-time countdown during the game in MM:SS format
  • Mines Counter: Visual indicator of remaining mines (total mines - placed flags)
  • Flags System: Right-click to mark suspicious cells, limited to the number of mines
  • Victory System: Automatic detection of victory when all safe cells are revealed
  • Quick Restart: Button to restart the game while keeping the current difficulty
  • Intuitive Interface: Clean design with visual feedback and status messages
  • Game Over: Automatic revelation of all mines upon losing
